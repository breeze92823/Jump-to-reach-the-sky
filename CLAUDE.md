## Current state: Jump to Reach the Sky (single player world + game server for saves, base seats, daily clock, leaderboards)
The game loop: train Jump Power on the AUTO TRAINING pads (auto-hops) and by jumping -> climb the lane's terraces (each wall needs more Jump Power) -> walk into brainrots to carry them overhead (a stack; the Carry upgrade raises how many) -> walk onto an empty pedestal at your base to place one -> it banks $/s on its green collect pad -> step on the pad (or Claim all) to collect -> buy pads, slots, wall skips, upgrades (Lucky Jumps / Speed / Carry), back items, perks, boosts, rebirth (needs Jump Power). Money is the only currency (no premium currency anywhere). The old boat game is in git `HEAD` (`git show HEAD:src/<file>`) if something generic is needed.

**Game server (`src/net.js`, `SERVER_URL` / `NET` in config)**: one Colyseus room `world`. **The room holds as many players as the hub has bases** (`HUB.plots.count` = 6 = backend `ROOM_MAX_CLIENTS` = the deploy's `roomSize`; keep all three equal). Each player gets a free base, its `seat`; `main.js` awaits `startNet()` (connects while the scene loads, waits at most `NET.bootWait` s) and calls `setLocalBase(seat)` BEFORE `buildHub`, which makes that plot the built one and moves `SPAWN` / the Home teleport to it (default base 2 with no server). The same first answer carries the saved progress of a signed-in account, which `load(doc, serverTime, userId)` applies over the local copy; `noProgress` (new account) keeps the local state and uploads it, `serverError` plays on the local copy with server saving off (never overwrites a save it could not read). After boot `state.js` `save()` feeds `saveHooks` and net.js sends `saveProgress` at most every `NET.saveEvery` s (immediately on tab hide / close / rebirth). Guests (no Bloxity sign-in) are never saved by the server: localStorage only (the local copy is tagged with its account `uid` and ignored by a different real account). Signing in/out mid-session: a new account with no save adopts the current state, one with a save reloads the page to load it. The same account in a second tab evicts the first (it shows a toast and does not reconnect). A late server answer (after `bootWait`) can't be loaded into the built game: `noProgress` starts saving, `progress` pauses server saving with a "reload to continue" toast.
- Daily Rewards clock (`src/game/daily.js`): for a signed-in player the SERVER's clock (net.js copies `dailyDay` / `dailyAt` into `game`, claims go through `requestDailyClaim` and rewards are only granted on ok; not connected = can't claim); guests and no-server run the same rules locally. `dailyDay` / `dailyAt` are never sent in `saveProgress`. The Claim All Pass and milestones stay client-side (`dailyPass`, `dailyMilestones` are saved).
- Leaderboards (`hub/leaders.js`): the server's top 16 for Total Money Earned (`totalEarned`) and Highest Jump Power (`jumpPower`) plus your rank, from `net.boards` / `net.ranks`; offline they fall back to generated names.
- **Bloxity SDK integrations (all in `src/bloxity.js`)**: besides init / auth / settings / avatar / loading / reserved areas / respawn: `getToken()` (sent to the server, which verifies it), `leaderboard.define` (config `LEADERBOARDS`; the server reports scores), ads (`onAdBreak` pauses the loop in `main.js` and mutes via `setSuspended`; `declareScreens({ panel, gameplay })`; `showAdScreen('panel')` / `hideAdScreen()` while a HUD window is open; one rewarded placement `free-boost` = the HUD "Free Boost" offer, config `ADS`, granted only on `completed`, with a cooldown), more settings (`master_volume`, `music_volume` = the ambience bed, `enable_chat`, `background_transparency` -> CSS `--panel-alpha`), chat bubbles over the local player (`onChatMessage` / `attachChatBubble`), emotes (`registerFeature('emotes')`, `play_emote`, catalogue fetched from `environment().apiUrl`, clips played by `src/avatar/emotes.js` after the animator and stopped on movement), friend-join toasts (`playerJoined` / `playerInRoom`, from `net.js` roster polling). Dev mode (no SDK) pretends a rewarded ad is available and completes it after 0.8 s. Character kit: `loadAvatar` in `main.js` dresses the cloned player.glb with `Legion.SDK.character.dress` (key from `avatar.getOutfitKey()`, bloxity.js `canDress` / `dressCharacter`); a look or proportion change calls `handle.update(key)` and rebuilds the manual way if that resolves false; with no kit / no key / a custom character the manual path (loader.js cosmetics + proportions) runs. Party play is automatic on Bloxity hosting (pinned SDK URL, matchmaker, room `maxClients` = 6, which also caps a party at 6): no code, just keep those conditions true. Not applicable / skipped: gems (never), death screen (the player cannot die), custom characters (the kit hands those back), the optional server stats.
- Other players are not drawn yet (no presence / remote avatars; the other bases stay blank pads). The roster (`net.room.state.players`, each with `username`, `pfp`, `seat`) is there for it.
- Local dev: run the backend (`npm start` in the backend folder, port 2567) and `npm run dev`; `VITE_SERVER_URL_DEV` (see `.env.example`) picks the server, empty = none. In dev mode (no SDK) the player is a per-browser signed-in `dev-xxxx` id, so a backend with `MONGODB_URI` keeps its progress; without Mongo the server answers `noProgress` and nothing is stored there. `__game.reset()` wipes the local save and the server's copy.

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the hub (`HUB`, `SPAWN`, `SPAWN_FACING`), `AUDIO`, `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers `net.js` uses (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
